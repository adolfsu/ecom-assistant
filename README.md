# 电商小助手（ecom-assistant）

面向抖店后台的 Edge 扩展工具集，用浏览器自动化把重复的商品运营操作批量跑掉。当前包含两个功能，后续会继续往里加。

## 功能

| 功能 | 做什么 |
|---|---|
| **批量填充 SKU** | 读 `.xlsx`，在商品规格编辑页逐条创建规格值，再填该 SKU 的价格与商家编码。每行表格 = 一条 SKU，可从完整 SKU 名自动拆出规格/单位/数量/量词 |
| **批量发布相似品** | 按商品 ID 列表，在商品列表页搜索 → 点「发布相似品」→ 确认 → 新标签页自动点「发布商品」→ 关标签 → 回列表继续下一条；失败会记录原因并汇总，支持一键复制 |

## 安装

1. Edge 打开 `edge://extensions`，开启左下角「开发人员模式」；
2. 点「加载解压缩的扩展」，选择本文件夹；
3. 打开抖店商品编辑页或商品列表页，点工具栏图标即可使用（也可「固定到侧边栏」，切标签页不消失）。

> 修改代码后，在 `edge://extensions` 点扩展卡片的刷新按钮，再**刷新抖店页面**（内容脚本不会热更新）。

```

app/sidepanel/    侧边栏：首页 / 功能中心 / 功能详情 / 任务中心 / 收藏 / 设置
app/shared/       设计系统（theme.css）、图标、DOM 与存储封装
core/             平台注册中心、功能注册中心、平台识别、消息总线、版本
platforms/douyin/ 抖店平台定义 + 两个功能的元数据（只有描述，不含执行逻辑）
content.js        抖店页面内的实际自动化（沿用 0.9.0，未改）
similar.js        列表页/发布页脚本（沿用 0.9.0，未改）
background.js     跨标签页协调（沿用 0.9.0，未改）
popup.html js css 0.9.0 旧面板，2.0 过渡期保留作回退入口
```

**当前进度：第一阶段骨架**。导航、首页、功能中心（搜索/平台筛选/分类筛选/收藏）、功能详情外壳、任务中心空状态、设置（主题/启动页/数据清理）已完成；两个功能的**操作界面仍在旧面板**，功能详情页底部提供「打开旧版面板」回退入口。

新增一个平台只需在 `platforms/` 下建 `platform.js` + `features/*.js`，再在 `platforms/index.js` import 一行——公共导航、筛选器、任务中心都不需要改。

## 开发记录

以下按版本倒序记录每轮问题的根因与改法，作为排障参考。

## 0.9.0 新增：发布失败记录原因 + 结果一键复制

批量跑「发布相似品」时，失败的那条以前会**整批停下**，而且只有一句笼统的原因。现在改成：

**① 失败不再中断整批。** 某条发布失败会记录原因后继续下一条，最后统一汇总；只有**连续 3 条**都失败（基本是页面改版/账号状态这类共性问题）才停下，避免白跑。

**② 失败原因尽量采到具体文案。** 发布页提交后同时盯两类提示：

- 浮层提示（toast / message / notification / alert）；
- 表单内联校验（`error` / `invalid` / `warning` / `danger` 类节点里的短文案）。

关键是**先记基线再比较**：点击「发布商品」前先记下页面上已有的提示，之后只认"新出现的那几条"。否则页面本来就挂着的「请选择类目」会被误判成本次失败原因。命中 `必填/不能为空/请选择/请上传/超限/违规/重复/已存在` 等关键词才算数，去重后最多 6 条。

**③ 结果区可直接复制。** 面板里显示「成功 N · 失败 M · 共 T 条」，下面逐条列出 `失败  商品ID  ← 原因`，并提供两个按钮：

- **复制全部结果** → `商品ID / 状态 / 失败原因` 三列；
- **只复制失败项** → `商品ID / 失败原因` 两列。

都是**制表符分隔、一行一条**，粘进 Excel / 飞书表格会直接分列，拿去重试或交付都方便。复制优先用 `navigator.clipboard`，面板没焦点时退回 `textarea + execCommand`，按钮会短暂变成「已复制」。

失败原因的传递链路：发布页 `error.issues` → `SIMILAR_PUBLISH_DONE` → 后台 → 列表页 `SIMILAR_NEXT` → `similarRun.results[].issues` → 面板。旧数据没有 `issues` 字段时自动退回 `reason`，不会显示空白。

新增 `tests/check-issues.js`：固定「差分只认新增提示」「多条原因合并」「复制文本列数/行数」等 16 项断言。

## 0.8.6 修复：搜索正常了，但弹窗一闪就没、不开新标签

**实机验证：0.8.6 用 3 条已发布过的商品连续跑通（搜索 → 弹窗 → 新标签 → 自动发布 → 关闭 → 下一条）。**

同时纠正一个此前的错误判断：**抖店并不拦截同一商品重复发布相似品**，同一 ID 可以反复发。所以“弹窗闪一下就没”不是平台拒绝，纯粹是点击没有真正落在「确认」上。

两个独立原因，各自都要处理：

**① 确认按钮可能被点成「遮罩」**。`mouseClick()` 默认用 `document.elementFromPoint()` 做命中测试（用于处理被遮挡的情况）。弹窗处于淡入/缩放动画期间，元素中心点很可能落到背后的遮罩上 —— 点到遮罩等于点「取消」，弹窗就闪一下消失。现在弹窗按钮一律**等就位后直接派发事件到按钮本身**（`mouseClick(el, {strict:true})`），"就位"＝位置连续 250ms 不变且中心点确实命中该按钮。

**② 合成点击没有「用户激活」，`window.open` 可能被浏览器弹窗拦截**。脚本派发的事件 `isTrusted=false`，不足以获得用户激活，平台确认回调里的 `window.open` 会返回 `null`：弹窗照常关闭，新页一个也没有。现在点确认前会在页面主世界安装一个钩子记录 `window.open` 的每次调用与是否成功；点完发现"弹窗关了但没新标签"时，由后台用 `chrome.tabs.create` 把同一个 URL 补开，流程继续。

配套：

- 点确认后 400ms 复查：弹窗还开着且后台没记录到新标签 → 补点一次（只补一次，避免重复提交）；
- 日志会明确写出「确认按钮：已就位/未就位」、`弹窗已关闭`、`平台的新页被浏览器拦下，已由扩展打开`、`平台没有尝试打开新页（捕获 window.open 0 次），可能被判定为重复发布` —— 下次一眼能分辨是"点歪了""被拦截"还是"平台拒绝"；
- `tests/check-dialog.js` 新增场景：坐标命中遮罩时仍必须点到「确认」；并断言实现走的是 strict 派发。

## 0.8.5 修复：搜索其实一次都没执行（真正的根因）

现象：搜索框里已经填了 ID，但列表仍是「共 3 件商品」原样不动；紧接着弹出「发布相似品」弹窗，闪一下就消失，没有新标签页；之后进入等待、超时、跳下一条。

截图里那条 ID 恰好就是列表第一行（上一次刚发过的商品）。`waitStableRefresh()` 开头有一句 `const hit = findUniqueResult(id); if (hit) return 'hit'` —— 本意是“ID 已精确出现在页面 = 搜索成功”，但**未筛选的列表里本来就可能有这个商品**。于是：

1. 一进循环就命中早已存在的行 → 返回 `'hit'`；
2. `triggerSearch()` 以为搜索已经生效，回车、点「查询」等动作**全部被跳过** → 表现就是“填了 ID 但根本没搜”；
3. 接着对那行点「发布相似品」，弹窗被点到遮罩、闪一下关闭，也没开新标签（当时误判成“平台拒绝重复发布”，实际只是点击没落在「确认」上）；
4. 旧逻辑还要干等 35 秒才判超时 → 表现就是“一直在等待”。

改法：

- **删掉 `'hit'` 这条捷径**。搜索生效的唯一证据是「表格内容在本次动作后发生稳定变化（连续 600ms 不变，且不为空）」；
- **加硬校验**：按商品 ID 查询后列表应当只剩 1 件。仍显示「共 N 件」（N>1）就直接报「筛选没有真正生效」并停止，绝不对着未筛选列表里的行点发布；
- **指纹基线必须基于有数据的列表**：先等到列表有内容再取基线，避免“空列表 → 渲染完成”被当成搜索刷新；
- **失败要快、原因要准**：点确认后同时盯弹窗与后台登记。弹窗已关闭、后台也没记录到任何新标签页，12 秒即判失败（不再干等 35 秒），并把平台 toast 文案带进错误信息；
- 新增 `tests/check-refresh.js`：用假时钟固定「列表未变时即便页面上已有该 ID 也不得判成功」「空列表/抖动不算刷新」「稳定变化才算刷新」四个场景。

## 0.8.4 修复：搜索判据再加固 + 全链路日志（定位"闪一下弹窗却没开新标签"）

现象（0.8.3 之后）：仍然观察不到搜索发生；「发布相似品」弹窗闪一下又消失，没有新标签页。说明流程又一次在“搜索没生效”的情况下走到了发布入口，而这个弹窗闪一下正是平台对重复发布不予打开新页的表现。

问题出在 0.8.3 的两个判据还不够硬：

- **指纹一次变化就算刷新**。表格加载时会先清空 tbody 再渲染，轮询恰好抓到中间态，就会误判“已刷新”。
- **兜底仍可能命中旧行**。若列表里显示的是商品编码而不是数字 ID，`previousIds` 文本匹配失效，就会把上一条的行当成这一条。

0.8.4 的改动：

- **指纹必须“稳定”**：新的表格指纹要连续保持 600ms 才算刷新；空指纹（骨架屏）一律不算。
- **兜底需要正向物证**：命中「共 1 件商品」那一行时，还要求页面留下“搜过这个 ID”的痕迹（搜索框里仍是该 ID，或出现「商品ID：xxx」筛选标签），否则返回 `untrusted`，直接跳过并提示，绝不点发布。
- **兜底再排除旧行**：命中行的文本若与搜索前指纹完全一致，判定为旧结果。
- **筛选标签不算结果**：精确匹配 ID 的节点若位于筛选栏/标签里（带「商品ID：」前缀且不在表格行内），不作为商品行。
- **搜索改成多步尝试链**：回车 → 点「查询」→ 再回车+查询 → 点搜索图标 → 失焦提交，每一步的超时与结果都写日志。按钮文案比较改为忽略空格（「查 询」也能认）。
- **输入前先真点一下输入框**：部分组件库只有收到真实 `mousedown/click` 才进入可编辑态；写入没留住时退回逐字符键入。
- **全链路日志**：列表页脚本通过 `SIMILAR_LOG` 把每一步写进面板的「运行日志」（与后台日志同一处）——认领了哪个搜索框（含 placeholder、坐标、当前值）、写入后的值、搜索前/后的表格指纹、每次尝试的结果、命中行文本、弹窗按钮、登记与接管结果。下次卡住可以直接照着日志定位。

## 0.8.3 修复：第 2 条起搜索不生效 / 没打开却显示「等待发布页」

单条跑通后测两条，出现两个看似独立的问题：① 第 2 条把 ID 输入了，但列表没真搜；② 第 1 条发布完关掉标签后，第 2 条并没有打开新页面，面板却显示「已打开发布页，等待…」。两者其实是**同一个根因**。

`findUniqueResult()` 末尾有个兜底：只要页面上出现「共 1 件商品」，就把那一行当作搜索结果。第 1 条做完后，列表正好停在第 1 个商品的「共 1 件商品」状态。第 2 条输入 ID 后：

- 回车若没被平台接受，**兜底先命中上一条的结果** → 插件认定“已经搜到了”，根本不会走「点查询按钮」的补救分支 → 表现就是“输入了 ID 但没搜索”；
- 接着对第 1 个商品点「发布相似品」，平台判定重复发布，不开新标签 → 但流程已经走完，直接播报“已打开发布页，等待…” → 表现就是“没打开却在等”。

0.8.3 的改法（三处一起，缺一不可）：

1. **不验证刷新就不认结果**：搜索前记录表格的「指纹」（前 5 行文本），输入后必须看到指纹变化、或 ID 精确出现在页面上、或出现「暂无数据」，才算搜索生效。空字符串（加载中的骨架屏）不算变化。
2. **兜底增加禁区和黑名单**：`findUniqueResult(id, { allowFallback: false })` 在“刷新未确认”阶段完全禁用「共 1 件商品」兜底；即使到了确认刷新后的阶段，若兜底命中的那一行里含有**前面已经处理过的 ID**，也一律判为旧结果、返回未找到。
3. **点确认后要验证标签页被真正接管**：新增 `waitTakeover()`，轮询后台的待处理登记，直到 `sent === true` 才播报“已打开发布页，自动发布中”；35 秒没接管就撤销登记并明确报错跳过，不再假装在等。

配套加固：

- 搜索框改为「全选 + insertText」一次性替换，避免“先清空再写”触发平台输入即搜、拿空值抢结果；写入后二次校验值没被受控组件回滚。
- 搜索触发顺序为：回车 → 点「查询/搜索」→ 再补一轮回车+查询；三次都没让列表变化才报「搜索没有生效」，不再靠猜。
- 「查询/搜索」的优先级高于「筛选」（点筛选只会开筛选抽屉，不会刷新列表）。
- 记住上一次真正用过的搜索框，列表刷新后优先复用，避免第二轮把行内编辑框误认成搜索框。
- 每条开始前清空可能残留的上一条信号（`earlySignal`），防止“提前收到结果”串位。
- 登记不上（后台被重载）时**不再点确认**，改为点掉弹窗并报错，避免开出一个没人接管的发布页。
- 后台在脚本注入彻底失败时也会回报失败，列表页不用再干等 4 分钟超时。
- 新增离线回归测试 `tests/check-search.js`：用真实函数仿真“列表还停在上一条”的页面，验证严格模式与兜底都不会命中旧结果。

## 0.8.2 修复：新标签页加载完却不自动发布 + 支持侧边栏

现象：点完「确认」后发布页正常打开、也加载完成，但流程停在「第 1/1 条：已打开发布页，等待发布结果…」，直到超时。

根因不在面板关闭，而在**登记时机**：`src` 端是在点「确认」之后 `await sleep(700)` 才发 `SIMILAR_OPENED`，后台此时才去 `chrome.tabs.query` 拍标签页快照——而新标签页在点「确认」的瞬间就创建了，于是**新标签页已经被包含在快照里**。等它 `complete` 时，后台的「只接管点击之后新出现的标签」判断命中 `before.includes(tabId)`，直接 return，永不触发；另一头列表页一直等信号，最后超时。

0.8.2 的改动：

- **先登记、再点确认**：`SIMILAR_OPENED` 改为在点「确认」之前 `await` 发送，后台拍快照时新标签页还不存在；点确认失败则补发 `SIMILAR_CANCEL` 撤销登记。
- **增加 `chrome.tabs.onCreated` 旁证**：记录本次点击新建的标签 id。即使该标签因某些原因出现在快照里，只要 `created` 里有它，仍然放行。
- 后台新增运行日志（`chrome.storage` 里最多保留 60 条），记录：登记任务 / 新标签出现 / 接管或拒绝的原因 / 触发发布 / 发布页回报 / 结果回传。面板里点「查看运行日志」即可看到，卡住时不用再猜。
- **侧边栏**：manifest 增加 `sidePanel` 权限与 `side_panel`（同样指向 `popup.html`），并调用 `setPanelBehavior({ openPanelOnActionClick: true })`。面板顶部新增「固定到侧边栏（切换标签页不关闭）」按钮，点一下把面板钉在窗口右侧，切标签页、开新标签都不会消失。全部是浏览器原生 API，不需要引入第三方库。

### 侧边栏说明

popup 面板一切换标签页就会关闭，这是浏览器行为，与流程是否继续**无关**（队列在列表页脚本里，后台负责接线）。侧边栏解决的是“看不见进度”，不是“跑不下去”。

如果你的 Edge 点图标仍然弹小窗，是因为 manifest 里同时保留了 `default_popup`（优先级更高）：点面板里的「固定到侧边栏」即可；也可以把 `manifest.json` 里的 `"default_popup": "popup.html"` 删掉，之后点图标就直接开侧边栏。

## 0.8.1 修复：两种确认弹窗都能点

实际弹窗和最初的假设不同：没有「发布相似品 / 设置渠道品」单选项，只有一句说明 + 底部「确认 / 取消」（标题为「确认发布相似品吗？」）。0.8.0 找的是「确定」按钮和单选项卡片，两处都对不上，报「确认弹窗里没找到「确定」按钮」。

0.8.1 改为两种形态同时兼容：

| 形态 | 长什么样 | 处理 |
|---|---|---|
| A 带单选项 | 列表第一项「发布相似品」，底部「确定 / 取消」 | 有单选项时先点第一项，再点底部确认 |
| B 纯文字确认 | 标题「确认发布相似品吗？」，底部「确认 / 取消」 | 无单选项时直接点确认 |

## 0.8.0 新增：批量发布相似品

### 使用步骤

1. 在抖店后台打开**商品列表**页（不是编辑页）；
2. 点扩展图标，在「发布相似品」区域粘贴商品 ID（每行一个，也支持逗号/空格分隔），或从表格某列读取；
3. 点「开始批量发布相似品」。之后可以关闭面板，流程会在列表页自己跑。

每条会依次执行：

```
列表页搜索该 ID → 等结果唯一 → 点「发布相似品」→ 先登记（拍标签页快照）→ 弹窗点「确认」
   ↓ 抖店自己打开新标签页
新标签页加载完成 → 点底部「发布商品」→ 等待「商品提交成功」
   ↓
关闭该标签页 → 回到列表页 → 下一条
```

### 实现要点

- **队列由列表页脚本驱动**，后台（`background.js`）只做三件事：记住列表页标签、盯住新开的发布页、完成后关标签页并把结果转回列表页。状态存 `chrome.storage`，所以**面板关掉、后台休眠都不会中断**批量。
- **发布页的触发是事件驱动的**：列表页点完「确定」后发 `SIMILAR_OPENED`，后台在 `chrome.tabs.onUpdated` 里等发布页 `status === 'complete'`，再通知它开始点发布；页面内容脚本没就绪时会自动补注入并重试 3 次。
- **信号有缓冲**：发布页可能在列表页进入等待之前就回报结果，`earlySignal` 会先存住，不会丢。
- **失败处理**：搜索不到 → 跳过并继续下一条；**发布失败 → 立即停止**并保留发布页（多为未登录、必填缺失或页面改版，不适合继续批量）。
- **安全边界**：只在列表页点「开始」时进入发布流程；没有任何自动触发，手动打开创建页不会被误发。

### 首次使用建议

选择器是按「文字 + 可点击性 + 行容器」推断的，不依赖固定 class。第一次跑如果报错，点面板里的**「检查列表页结构」**，它会打印：可见搜索框及其 placeholder/坐标、认领到的搜索框、「发布相似品」候选按钮、「发布商品」按钮、表格行数与首行文本、当前确认弹窗。把这段发出来就能一次校准到位。

### 验证脚本

这一版新增了跨标签页协议（列表页 → 后台 → 发布页 → 回列表页），对应的离线检查脚本只在本地保留，未随仓库发布。其中 `check-messages.js` 是为该协议准备的静态扫描：第一版就漏了「后台通知发布页点发布」这一环，静态扫描能直接发现这类"发了没人听/听了没人发"的问题。

## 0.7.1 修复

现象：批量 0/13，提示「第13条 …：SKU 名称已填入；规格数值已填入；数量已填入；规格单位 页面重绘后没有找到规格编辑框」——三段落文本都进去了，却卡在选下拉。

根因：`findEditor()` 只有「输入商品描述」一个锚点，而那是**占位提示元素**，几个文本框填满后会被页面隐藏；`createOne()` 又每填一个字段就重新调一次 `findEditor()`，于是轮到「规格单位」时定位失败。

0.7.1 的改动：

- `createOne()` 先拿一次编辑框和字段节点，之后**节点还在文档里（`isConnected`）就直接用**，失效才重新查找；重新查找失败时用原容器再识别一次。彻底去掉“每步都重找”的依赖。
- `findEditor()` 增加多个锚点（「输入商品描述」「请输入规格值」），并新增兜底：从「填写并新增规格值」入口往上找，它不随填值消失；向上搜索层数 10→14，同时给下拉数量加上限（2~4），避免爬到「价格库存」整表容器。
- 结构识别失败时的报错会直接说明是哪个输入框没认出来。

## 0.7.0 新增：不用再手工拆 SKU 名

以前表格要备好 5 列：`组合名称 / 规格 / 规格单位 / 数量 / 数量单位`。现在**只要一列完整名**即可，扩展会自动拆出后四项。

拆分规则（`parser.js`）：

- 只认**最靠右**的那一组 `数值+单位 * 数量+量词`，且必须**紧贴名称结尾**；
- 其余部分全部保留为名称；
- 名称里天然带的 `*6`、`*4袋` 不会被误拆：`*6` 后面没有量词，`*4袋` 前面没有「数值+单位」；
- 结尾没有规格结构时**不做猜测**，直接报“未识别”并列出具体行号。

例（示例品名为虚构）：

| 表格里写的完整名 | 名称 | 规格 | 单位 | 数量 | 量词 |
|---|---|---|---|---|---|
| 收纳袋A\*6+收纳盒B\*2+补充装2500g\*1袋 | 收纳袋A\*6+收纳盒B\*2+补充装 | 2500 | g | 1 | 袋 |
| 收纳袋A\*4袋+补充装130g\*4袋 | 收纳袋A\*4袋+补充装 | 130 | g | 4 | 袋 |

配套改动：

- 面板新增开关「名称已含规格时自动拆分」，默认开启。关闭后完全按手工列走。
- **已映射/已填好的列优先**，只有空着的字段才由名称补。因此旧的 5 列表格仍然照常可用，不会被改动。
- 名称会自动截掉尾部规格段（否则抖店的 SKU 名称会和规格值重复）。
- 面板会显示「已按名称自动拆分 N 条」或「M 条名称没识别出规格：第 X 行…」，鼠标悬停可看每行原因。
- 表头映射只需指认 `组合名称`、`商品编码`、`售价` 三列，其余四个下拉保持「不导入此列」。

验证方式（含真实新表）：

用离线脚本把「完整 SKU 名 → 拆分结果」与手工拆好的 5 列表逐字段比对，并验证表头自动定位。这些脚本依赖真实商品样本数据，仅在本地运行，未随仓库发布。

结果：拆分与新表比对均为 13/13 完全一致；表头自动选中第 12 行（得分 3），
`组合名称 / 商品编码 / 售价` 正确识别，其余 4 字段留空交给自动拆分；
表尾「设计工单 / 评价内容」等说明行被候选门槛正确忽略；另有 4 条“不该拆的名称”全部正确拒绝。

## 0.6.0 修复（重要）

0.5.x 用“像素位置就近”认领输入框，会把规格单位下拉框内部那个**只读搜索 input** 当成「规格数值」，于是报 `规格数值 输入项为只读` 并整批停下；由于该只读框排在最左的 SKU 名称之后，只有名称能填进去。

0.6.0 的改动：

- 改为**按文档顺序**识别规格行：`[名称] [规格值] [规格单位▾] * [数量] [数量量词▾]`，取“第一个下拉之前倒数第二个输入框 = 名称、倒数第一个 = 规格值、两个下拉之间 = 数量”。
- 先找出下拉框外壳（兼容 Semi / Arco / 原生 select），把外壳及其内部的搜索框整体排除出文本字段，只读搜索框不再被误认。
- 下拉选择重写：点击外壳展开 → 在新出现的 `[role=option]` 里按文本匹配（先精确、再包含）→ 点击 → 校验外壳文本是否更新；失败时才补一次鼠标序列，避免把已展开的面板点回去。找不到选项时会回报该下拉里真实有哪些文字。
- 遇到只读字段不再直接放弃，先解除只读再写值。
- 新增「检查页面规格框结构」按钮：把当前规格编辑框里识别到的下拉框、输入框（含 placeholder、只读状态、位置）和最终认领结果打印出来，方便对照排查。

## 0.6.1 修复

0.6.0 后文字段（名称/规格值/数量）已正常，但报 `规格单位 下拉框没能打开，找不到「g」`。

根因：`dropdownHosts` 取的是“最外层匹配 `[class*="select"]` 的容器”。抖店的单位下拉外面还套了一层 `xxx-select-wrap`，`element.click()` 打在外壳上，事件只会**向上**冒泡，永远触发不到内层真正绑了 `onClick` 的下拉核心，所以面板不展开。

0.6.1 的改动：

- 拆出「识别宿主」和「点击锚点」：宿主仍取最外层（用于几何定位），点击改为落在**内层下拉核心**（`clickAnchor()`）。若仍失败，再依次尝试：完整鼠标序列（pointerdown/mousedown/pointerup/mouseup/click）→ 按坐标用 `elementFromPoint` 找真实元素点一次 → 方向键展开 → 可搜索下拉直接键入文字后回车 → 隐藏原生 select 兜底。
- 每次尝试前用 `isConnected` 校验节点是否已被页面重绘替换，失效就按字段名（specUnit / quantityUnit）重新识别并取新节点。
- 失败提示会附带“点击目标”的真实 class 和位置，便于定位。

## 0.6.2 修复

0.6.1 能完整填完第一条，但报 `点击“填写并新增规格值”后没有出现下一条编辑框`。

根因：抖店的实际交互是「填写完成 → **点空白处**让当前填写框收起、规格值才落成上面的规格值条 → 再点“填写并新增规格值”才会出现下一条空白框」。0.6.1 直接去点“填写并新增规格值”，那一下只是把还开着的弹层关掉，所以拿不到下一条。

0.6.2 的改动：

- 新增 `commitEditor()`：在文档层面补一次完整鼠标序列（pointerdown/mousedown/pointerup/mouseup/click）模拟“点空白”，直到规格填写框真正收起（最多重试 4 次）。
- `openEditor()` 改为「先收上一条、再点新增」；若第一下只是关掉残留弹层，会自动再点一次。若残留编辑框里还有上一条名称，会先提交再开新的，避免把新数据覆盖到上一条。
- `findAddTrigger()` 改为优先取**当前为空**的那个输入框：已创建的规格值行会占用同一个 placeholder，取错会去编辑旧规格值。
- 价格与库存行的价格/编码定位，排除了“套餐类型”下拉内部的只读搜索 input；等待规格行出现的时间放宽到约 5 秒。

## 0.6.3 修复

0.6.2 能跑到 10/13，但出现两类错：某几条报「sku 已存在」并把价格写进了**别人的行**；末尾两条报「规格值没有出现在价格与库存列表中」后整批停止。

根因在行定位：旧版用「行文字**包含**名称 + 包含规格 + 包含数量」来认行。而这批数据里存在大量**互为前缀**的组合名（如 `收纳袋A*4袋+补充装` 与 `收纳袋A*4袋+补充装B`，多行都含「*4袋+…」），一个**跨了多行的容器元素**就能同时凑齐三个片段，于是被当成"已存在的行"，价格写进了容器里的第一个价格框（也就是上一行）。

0.6.3 的改动：

- 行定位改为**整串精确匹配**：价格与库存表里一条 SKU 的「套餐类型」文字，正好等于 `名称+规格+单位+数量+量词` 拼起来的整串，先把这段文字定位出来，再往上找**只包这一条**的容器（容器文案不能超出 key 40 字，且输入框数量在 1~5 个之间，跨行容器会有 8 个以上）。
- 价格/编码改为按**列位置**定位：该表列序是 `全部套餐类型 | 价格 | 现货库存 | 商家编码 | 条形码`，排除下拉框内部搜索框后，一行剩下的输入框依次就是 价格、库存、编码、条码；先按提示词匹配，再按位置兜底。
- `waitForRow` 放宽到约 7.6 秒，中途若仍无行会再补一次“点空白提交”。

## 安装与使用（批量填充 SKU）

1. 按上文「安装」加载扩展；改过代码就在 `edge://extensions` 点刷新，然后刷新抖店页面。
2. 打开抖店商品编辑页，展开“商品规格”区域。页面需要显示“填写并新增规格值”空白项。
3. 点扩展图标，选择商品 `.xlsx` 文件。工具会自动识别“组合名称、规格、规格单位、数量、数量单位、商品编码、售价”等列，检查表头行与列映射。
4. 点“批量创建并填写所有 SKU”。扩展会打开空白规格项，按表格行填写名称、规格数值和单位、数量和量词，随后查找对应的价格库存行并填写价格和编码。第一条创建成功后会继续点开下一条空白项，无需预先准备 SKU。
5. 查看商品页逐条结果。检查全部 SKU、价格和编码后，在抖店页面自行保存商品。

当前样本表第 12 行是表头，包含批量创建所需的七列。普通说明行因缺少必填字段会被跳过。价格必须大于 0，工具会在操作抖店页面前检查整批数据。当前样本 13 条 SKU 的“售价”公式都引用空白 I 列，因此计算结果为 0。请先补上实际售价或修正售价公式。

## 页面行为

- 不要求先有已创建的 SKU。扩展会使用“填写并新增规格值”空白项打开规格编辑框。
- 已经存在的相同名称、规格和数量组合会复用对应行，避免重复创建。
- 每行创建后，页面提示会列出价格和编码是否已写入。若当前抖店版本将编码放在“批量设置”或行编辑弹层中，工具会尝试按可见标签定位对应输入项。
- 规格编辑器按文档顺序重新识别名称、规格数值和数量，并在页面重绘后重新查找字段。文本项先填好，再选择规格单位和数量量词。
- 商品页会报告识别不到编辑框、单位选项、价格行或编码输入框等问题。遇到规格框无法关闭或新规格没有进入价格库存表时，扩展会停止后续行，避免把下一条数据写入上一条。
- 扩展只操作当前商品编辑页，不会点击保存或发布按钮。

## 更新扩展

在 `edge://extensions` 点扩展卡片上的刷新按钮，然后刷新抖店商品编辑页，再重新打开扩展。
